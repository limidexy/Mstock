# 云端使用说明

旧电脑不在身边时，先使用 GitHub Actions 运行源码验收。无需复制旧电脑环境，也无需提供项目密钥。

## 打开和运行

1. 打开 [云端源码验收](https://github.com/limidexy/Mstock/actions/workflows/cloud-check.yml)。
2. 点击“运行工作流”（Run workflow），选择 `main`，再点击运行。
3. 等待运行结束，打开该条记录查看中文摘要。
4. 需要排查时，在该记录底部下载 `Mstock-cloud-check` 验收附件；附件保留七天，之后可以重新运行生成。

修改源码、依赖或测试并推送到 `main` 时也会自动验收；相关拉取请求同样运行检查。没有创建按时执行的周期任务。

## 当前能够验证的范围

使用 GitHub 托管的标准 Windows 2022 环境和 64 位 Python 3.12.4，按现有 `requirements-windows-lock.txt` 安装依赖，再执行依赖检查、源码编译和全部测试。测试会自行生成隔离模拟样本，不依赖真实行情或人工校对。原有迁移基线有 113 项测试，后续以每次运行摘要中的实际统计为准。

验收附件只包含测试 XML、实际依赖版本和验收说明。工作流使用只读仓库权限，不接触仓库密钥，不提交运行产物，不修改行情、校对文件或评分规则。官方 Actions 固定到经过查询的提交版本。

初始化环境会联网获取源码、Python 与公开软件依赖；业务测试仍使用离线模拟数据。环境变量 `MSTOCK_ENABLE_NETWORK=false` 不是整个项目的强制断网屏障，因此工作流只执行已明确为离线的测试入口，不运行行情下载或每日选票脚本。

## 真实数据与后续使用

当前云端验收不生成今日真实候选，不恢复旧电脑的 1414 个历史文件，不代表策略收益或新电脑现场恢复完成。

历史人工校对和历史报告需要旧电脑私有交付包，无法从 GitHub 重建。公开行情可在用户确认允许联网获取后另行下载，但新下载的数据不能冒充原始备份或用于声称原文件校验通过。私人交付包仍不得上传本公有仓库。

本入口是按次运行的云端验收工具，不是持续在线的网站或云端桌面。需要接续开发时继续读取 `AGENTS.md`、迁移交接资料和开发接续说明。原迁移提交与两个迁移标签保持不变。
